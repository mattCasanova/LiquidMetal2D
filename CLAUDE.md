# LiquidMetal2D

Swift/Metal 2D game engine library for iOS and macOS.

## Project Overview

- **Language:** Swift 6
- **Graphics:** Apple Metal
- **Platform:** iOS 26+ and macOS 26+ (native AppKit, not Catalyst). Platform code is guarded `#if canImport(UIKit)` … `#elseif canImport(AppKit)`, UIKit first so Catalyst takes the iOS path (a Mac-only file or block uses `#if canImport(AppKit) && !canImport(UIKit)`); never `#if os(macOS)`
- **Package Manager:** Swift Package Manager
- **Dependencies:** SwiftLint (build plugin only — no external runtime deps)
- **Tools:** Motionator, the Mac animation tool, lives in `Tools/Motionator/` (its `CLAUDE.md` has the layout): `Motionator.xcodeproj` (the SwiftUI document app, Mac only, in the root workspace) and `MotionatorKit`, a plain SwiftPM package (document model, editing operations, a headless contact-sheet renderer and the `motionator` command) that both depend on this checkout; `swift build` / `swift test` at the root ignore them
- **Demo:** the demo app lives in `Demo/` (`Demo/LiquidMetal2D-Demo.xcodeproj`, sources in `Demo/LiquidMetal2D-Demo/`, its own `CLAUDE.md`) and builds against this checkout through a local package reference. An engine change and its demo change land on the same branch: no tag, no version bump. `LiquidMetal2D.xcworkspace` at the root opens the package and the demo together. The demo is a SwiftUI app on `LiquidView` that runs on iPhone, iPad and the Mac from one target; both builds are gates for an engine change. `swift build` / `swift test` ignore `Demo/`

## Architecture

- **Graphics** (`graphics/`) — Metal rendering pipeline
  - `renderers/` — orchestration: `Renderer` protocol, `DefaultRenderer` (open for subclassing), `RenderCore` (Metal device/layer/queue)
  - `shaders/` — `Shader` protocol + built-in shaders (`AlphaBlendShader`, `WireframeShader`, `RippleShader`, `ParticleShader`) and their matching `*Pipeline` factories (`LightPipeline` serves `LightMap`)
  - `textures/` — `TextureManager` (async loading, ref counting, error/default textures, 64×64 procedural soft-circle particle texture), `TextureDescriptor`, `Texture`
  - `uniforms/` — `ProjectionUniform`, `AlphaBlendUniform`, `WireframeUniform`, `RippleUniform`, `ParticleUniform`, `LightUniform`, `LightVertex`: plain structs whose fields mirror the MSL struct in order. `UniformData` gives `stride` (= `MemoryLayout.stride`, padding included) and `store(into:index:)`, one store per instance. `UniformLayoutTests` pins every stride and offset. **No per-sprite matrices:** each sprite uniform carries a `Transform2D` (position, scale, rotation, zOrder) and the vertex shader builds the transform with `spriteWorld`, one copy per `.metalSource` (`SpriteTransformTests` runs every copy on the GPU against `Mat4.makeTransform2D`). Only `ProjectionUniform` is a matrix, once per frame
  - `shaders/DrawList.swift` — `DrawList<Comp: TexturedComponent>`: the per-frame `(GameObj, Comp)` list, sorted `.farToNear` (`zOrder`, then `textureID`; default) or `.byTexture`, reused across frames (no per-frame allocation). `AlphaBlendShader`, `RippleShader` and `ParticleShader` all use it
  - `shaders/InstanceBatches.swift` — internal value type: one frame's instance count and texture runs (one instanced draw per run). The textured shaders' `submit` swaps it into a local for the per-instance loop; `flush` drops the drawn runs but keeps the count, so later submits in the frame take the next slots
  - `metalHelpers/` — `BufferProvider` (triple-buffered semaphore)
  - `Camera2D`, `PerspectiveProjection`, `OrthographicProjection`, `RenderPass` (generic — owns encoder/drawable/command buffer)
- **Components** (`components/`) — `Component` protocol + render-state components: `AlphaBlendComponent`, `WireframeComponent`, `RippleComponent`, `ParticleEmitterComponent` (owns particle pool), `SkeletonComponent` (see Animation). `TexturedComponent` (`textureID`) is the refinement `DrawList` sorts by; the alpha-blend, ripple and emitter components conform
- **Animation** (`animation/`) — 2D skeletal animation. Pure data, no `@MainActor`, so tests and tools use it anywhere:
  - `SkeletonDefinition` (a rig: `Bone`s parents-before-children, `Attachment` quads pinned to bones; `validate()` throws `SkeletonError` by name), `RigidTransform2D` (position + rotation, no scale, so bone chains stay rigid), `Pose`, `SkeletonSolver.solveWorld` (one forward pass)
  - `AnimationClip` (per-bone `Keyframe` tracks with `EasingType`, named `AnimationEvent`s; bones by name) → `resolved(for:)` → `ResolvedClip` (bone indices, sampled without string lookups)
  - `Animator`: layers (layer 0 from rest; higher layers override only the channels they key), crossfades, weights, one-shots, `onEvent` / `onClipFinished`; five preallocated poses, no allocation in steady play
  - `SkeletonComponent` on a root `GameObj`: every `update(dt:)` writes one ordinary `GameObj` per attachment into `parts` (submit them with the scene); `place(pose:)` places them from a pose a tool sampled itself, bypassing the animator; `scale`, `flipX`, per-attachment visibility, `worldTransform(ofBone:)` for muzzle points and hit tests
  - Two-bone IK: `TwoBoneIK.solve` is pure (a posing tool can call it); `IKConstraint` is checked against the rig when built; `SkeletonComponent.ikConstraints` applies on top of the animation (the animator's pose is untouched), through `flipX` and a moved or scaled root. Move a target in place; no allocation
  - Files: `AnimationFiles` reads `name.rig.json` / `name.clip.json` (JSON5; fields with a default in code may be left out) and writes pretty, key-sorted JSON. `AnimationFilesTests.testFilesInTodaysShapeKeepLoading` pins the key names: renaming a stored property or enum case breaks every file written, so it needs a decode path for the old name. Angles in radians; no version key yet (absent = version 1)
- **Scene Management** (`scenes/`) — Stack-based transitions (push/pop/set) via `SceneManager`. `SceneType` is a `Hashable` protocol (use an enum). `SceneFactory` maps each type to its `Scene.Type` (`addScene`/`addScenes`; the scene's own `sceneType` is the key). `DefaultScene` base class with built-in scheduler and object list
- **Game Engine** (`engine/`) — `GameEngine` protocol + `DefaultEngine`. Main loop paced by a `FrameClock` (`DisplayLinkClock` wraps the platform `CADisplayLink` in the `.common` run-loop mode, so frames keep coming while a scroll view or menu tracks; before its first frame it reports the host time, not 0, so a start or restart doesn't clamp the first frame; `DefaultEngineTests` steps a fake) with dt clamping. Full shutdown chain (engine → scenes → renderer)
- **App lifecycle** (`engine/AppState.swift`, `engine/AppStateSource.swift`) — `AppState`: `.active`, `.inactive` (visible, no focus: Command-Tab, the game window not key, Notification Center), `.background` (not visible: iOS home, Mac minimise or hide). `AppStateSource` maps iOS notifications straight to states and derives the Mac state from app active/hidden and the game window key/minimised (other windows ignored; no window yet reports nothing). On a change `DefaultEngine` tells weak `AppStateObserver`s (app-level: saving) first, then the current scene (`Scene.appStateChanged(to:)`, empty default); performs any pending transition at once, so a pushed pause scene is current while the player is away (a SwiftUI overlay shows at once; Metal content waits for the first frame back); the next frame drops its input events as a transition frame does; then stops the clock in the background always and while inactive unless `pausesWhenInactive: false`, and restarts it on return measured from the return. **The engine never pauses, shows UI or saves for the game**: push your own pause scene on **any state other than `.active`** when it isn't already up (a Mac minimise can skip `.inactive`; `.inactive` also arrives on the way back), save on `.background` (iOS may end the app after it without notice). `engine.appState` reads the latest; the API lives on `DefaultEngine`, so keep a typed reference. An app launched hidden counts as active until its first focus change; observers must not spin a nested run loop
- **Lighting** (`lighting/`) — a 2D light map with shadows. `Light` (position, z, radius, colour, intensity, falloff; `halfAngle` < π makes a cone along `direction`, `edgeSoftness` fades its edges). `LightMap` (`renderer.makeLightMap(...)`): per frame `begin()` → `ambient` → `add(light, outline:)` → `commit(viewProjection:)` **before** `beginPass`; it draws the lights as fans of triangles into its own `rgba16Float` texture (`resolutionScale`, default 0.5, of the drawable) on its own command buffer, the fragment shader doing the distance falloff and cone fade, lights adding. Then, inside the pass, `renderer.composite(lightMap)` multiplies the texture over everything drawn so far (flushes the active shader, which stays bound) and what is submitted after stays bright (emissive). Shadows: pass a `VisibilityPolygon`'s `points` as the `outline` (closed for a pool, open for a cone); walls are `LineSegment`s. A light costs 3 vertices per outline point. `radius` 0 is a light turned off; a negative radius, `falloff` ≤ 0 or a `halfAngle` outside (0, π] asserts. `add` allocates nothing; `LightMapTests` read the texture back and check pixels by world position; `UniformLayoutTests` pins `LightUniform` (48 bytes) and `LightVertex` (16). Not in scope: normal maps, soft shadows, sprites casting shadows, reading the map back for gameplay
- **Input** (`input/`) — one event queue, drained once per frame. Platform code only `enqueue`s `RawInputEvent`s (`down`/`up` of an `InputCode`, `pointerMoved`, `scroll`, `touchBegan`/`Moved`/`Ended`, `focusLost`); `InputSystem.beginFrame()` (called by `DefaultEngine` at the top of each frame, before the transition check) turns them into state and the frame's `[InputEvent]`. Scenes poll through `InputReader` with Mach 5's vocabulary (`isPressed`, `isTriggered`, `isReleased`, `isRepeating`, `isAnyTriggered`; over sets, `isPressed(anyOf:)`/`(allOf:)`, `isTriggered(anyOf:)`, `isReleased(anyOf:)` and `isComboTriggered` (all held, one went down this frame, modifiers it does not name are up whenever the keyboard is on, so Command-Z stays quiet inside Command-Shift-Z; an empty set traps; a code of a device that is off counts as never down, so one binding list can name keys and gamepad buttons); `.shift`/`.control`/`.option`/`.command` are derived either-side codes, never enqueued (a modifier press sends both events; a replay tool must skip the derived one); `pointer.location`, `pointer.touches`, `pointer.scrollDelta`, `pointerWorld(forZ:)`; the old `getScreenTouch`/`getWorldTouch` still work) or observe through `DefaultScene.inputObservers` (`PointerObserver`, `KeyboardObserver`, `GamepadObserver`; weak; the engine delivers to the current scene only and a transition frame drops its events). `InputCode` is one `Int`-backed enum for pointer buttons, keys and gamepad buttons, each knowing its `InputDevices` member. The raw value is only a table index and shifts when a case is added; files save codes by case name (`InputCode+Codable`, pinned by `InputCodeCodableTests.testFilesInTodaysShapeKeepLoading`), so renaming a case needs a decode path for the old name. Devices are opt-in at `DefaultEngine(inputDevices:)` (default `[.pointer]`); querying a device that is off traps, feeding one is dropped with a Debug line. Sources: `LiquidViewController` (touches, iPad hover, Mac mouse/hover/scroll, only for enabled devices), `KeyboardSource` (`GCKeyboard`, both platforms; the Mac host view swallows key events so nothing beeps), `FocusSource` (releases everything on focus loss). Gamepad is the plan's Phase 6, not built. Actions: a game declares a `String`-backed enum conforming to `InputAction` (like `SceneType`) and binds each case to a list of codes in `InputBindings<Action>` (every case must have a default; an empty list is never down). Scenes ask `isPressed`/`isTriggered`/`isReleased(_:in:)` and `axis(negative:positive:in:)`; a controls screen remaps (`set`/`add`/`remove`/`reset`), finds conflicts (`actions(boundTo:)`) and captures with `firstTriggeredCode()` (modifiers come back either-side). `saved`/`restore` keep the table as `[String: [InputCode]]` for any `Codable` store; actions added since a save keep their defaults, removed ones are skipped. Modifier shortcuts stay `isComboTriggered`, not bindings
- **Game Objects** (`dataTypes/`) — `GameObj` (`final`: position, velocity, scale, rotation, zOrder, isActive, components) — **no subclassing, compose via components**. Plain value types: `Transform2D` (what shaders draw from; `GameObj.transform` reads and writes the four fields as one; `Transform2D(rigid, scale:, zOrder:)` places a quad at a `RigidTransform2D`), `Particle` (particle pool data), `WorldBounds`, `UnprojectRay`. The `Component` protocol + render components live in `components/`.
- **Colliders** (`collision/`) — `Collider` protocol with double-dispatch in `collision/colliders/`: `CircleCollider`, `PointCollider`, `AABBCollider`. `SpatialGrid` (broad phase): `forEachPotentialPair` and `forEachNear` allocate nothing in optimized builds; `potentialPairs()` / `query(near:)` return arrays for convenience
- **Math** (`math/`) — no external dependency
  - `GameMath` enum — clamp, wrap, lerp, inverseLerp, remap, smoothstep, bezier curves, angle conversion, float comparison
  - `Easing` enum — quad, cubic, quartic, sine, expo, elastic, bounce, back (in/out/inOut)
  - `Intersect` — point/circle/AABB/line-segment collision tests, `raySegment` (distance along a ray to a segment)
  - `VisibilityPolygon` — the outline a light or a guard's eyes reach before walls stop it: an angular sweep (wall corners with a nudge either side, 48 spokes, a cone's edges), rays shortened by `Intersect.raySegment`, points counter-clockwise, buffers reused (zero allocation in steady state, sorted by an in-place heapsort because `sort()` allocates). A light on a wall's line sees only the wall's right side, so counter-clockwise boxes keep their inside dark. Pure; Seoul Noir's `GameCore` may copy it
  - `Projection` — project/unproject between world and screen coordinates
  - `extensions/` — `simd_float2+`, `simd_float3+`, `simd_float4+`, `simd_float4x4+` (cross2D, to3D, lerp, setToTransform2D, etc.)
  - `shapes/` — `AABB`/`MutableAABB` and `Circle`/`MutableCircle` protocols; `LineSegment` (a wall; `appendEdges` makes a box's four, counter-clockwise)
  - `TypeAliases` — `Vec2`, `Vec3`, `Vec4`, `Mat4` (aliases for simd types, `@_exported import simd`)
- **Behaviors** (`behaviors/`) — `Behavior`/`State` protocols for game logic state machines
- **Scheduling** (`scheduler/`) — `Scheduler` with pause/resume, `ScheduledTask` with repeat count, chaining (`.then`), completion callbacks. Action receives `dt`
- **Persistence** (`persistence/`) — Two-tier split by who owns the file:
  - **App-owned** — `BlobStore` protocol (key-value `Data` CRUD, throws) with `FileBlobStore` (writes to `Documents/<subdirectory>/<key>`) and `InMemoryBlobStore` (dict-backed, for tests; throws `KeyNotFoundError`). `CodableBlobStore<T>` wraps any `BlobStore` and handles JSON encode/decode for any `Codable` type. Callers construct the underlying `BlobStore` themselves so tests can substitute `InMemoryBlobStore` without a code-path change.
  - **User-owned** — `DocumentIO` (`final class`) wraps the system file picker in async/await: `UIDocumentPickerViewController` in `DocumentIO+UIKit.swift`, `NSSavePanel`/`NSOpenPanel` sheets in `DocumentIO+AppKit.swift`. Created once at app startup with the presenting view controller (a `PlatformViewController`, stored weakly); scenes call `save(data:suggestedFilename:)` / `load(contentTypes:)` without seeing UIKit or AppKit. `DocumentIO.Error.userCancelled` surfaces picker dismissal; I/O errors propagate as their underlying Cocoa type. The UIKit picker delegate's lifetime uses a self-retaining coordinator (`selfRef = self`, cleared in callback).
- **View Controllers** (`viewControllers/`) — `LiquidViewController`, one class per platform with the same name and API (feeds raw input events in top-left screen space for the enabled devices: touches and iPad hover, or the Mac mouse with hover, buttons and scroll; resize on layout; shutdown on disappear); `LiquidNSView` (the Mac host view: first responder, backing-scale changes, hover tracking, swallows key events when the keyboard is on); `LiquidView` (SwiftUI bridge, `UIViewControllerRepresentable` / `NSViewControllerRepresentable`); `GameWindow` (the SwiftUI scene a game's `App` declares, same name on both platforms: a plain `WindowGroup` on iOS; on the Mac one `Window`, close button and Command-W off, Quit gone from the menu so Command-Q does nothing, document and editing menus emptied, `fixedSize:` optional; replacing a command group the default menu bar lacks adds an empty menu, so `.textFormatting` is left alone); `LiquidApp.quit()` (Mac only: the game's own Quit button calls it after whatever prompt it wants; the engine never prompts). On the Mac every quit, this one or a deliberate system one (the Dock, log out, shut down), runs `DefaultEngine.shutdown()` through `willTerminateNotification`, so scenes get `shutdown()` and save there; `shutdown()` runs once whoever asks
- **Platform** (`platform/`) — `PlatformTypes.swift`: `PlatformView` (`UIView` / `NSView`) and `PlatformViewController` typealiases. `UIView` and `NSView` share no base class, so the engine names them through the aliases and guards only the spots whose APIs differ (`RenderCore`'s host layer and content scale, `DisplayLinkClock.makeLink`, the view controllers, `DocumentIO`'s backends, the input and app-state sources, `GameWindow`, `LiquidApp`)
- **Utilities** (`util/`) — `Debug` helpers, `SeededRandom` (SplitMix64 `RandomNumberGenerator`; pass it to `ParticleEmitterComponent(random:)` for a repeatable effect or exact tests)
- **Resources** — `AlphaBlendShader.metalSource`, `WireframeShader.metalSource`, `RippleShader.metalSource`, `ParticleShader.metalSource`, `LightShader.metalSource` (bundled, loaded at runtime; adding one leaves stale resource bundles in reused build folders, so clean once)

## Rendering Pipeline

- `RenderCore` owns the Metal device, command queue, CAMetalLayer, camera, projections, and `TextureManager`
- `RenderPass` is generic — owns encoder/drawable/command buffer, has no shader knowledge
- `Shader` protocol encapsulates pipeline state + uniform format + per-frame buffer + batching. Each shader owns its own `BufferProvider` sized to its own uniform stride × its own `maxObjects`
- `AlphaBlendShader` is the built-in default. Filters objects by `AlphaBlendComponent` presence — objects without one are silently skipped
- `DefaultRenderer` owns one `AlphaBlendShader` (exposed as `renderer.alphaBlend`) and tracks the currently-bound shader on the pass
- Draw flow: (lights first, on their own command buffer: `lightMap.begin()` → `add` → `commit()`) → `beginPass()` → `usePerspective()`/`useOrthographic()` → `useShader(shader)` (optional; `submit` auto-binds alphaBlend) → `submit(objects:)` → `composite(lightMap)` (optional: multiplies the light map over the scene so far; later submits are emissive) → `endPass()`. Switching shaders mid-pass flushes the previous shader's batches. `DefaultRenderer.makeRenderPass()` is `open` so tests draw into a readable texture
- Multi-shader per object: attach multiple render components (e.g., `AlphaBlendComponent` + `WireframeComponent`) to one GameObj and each shader picks up its matching component. No duplicate objects
- Advanced manual path: `renderer.alphaBlend.draw(_ transform: Transform2D, texTrans:color:textureId:)` (e.g. `draw(obj.transform, textureId: id)`) — per-call, no sort, batches consecutive same-texture calls
- `submit(objects:)` sorts by `(zOrder, textureID)` via `DrawList` and batches by texture for instanced drawing. Ascending `zOrder` is far-to-near (the camera sits at `z = distance` looking down −z), so the painter's order is ascending. Components build their uniform with `makeUniform()`
- **Alpha is premultiplied end to end.** `Texture` decodes PNGs premultiplied (`CGImageAlphaInfo.premultipliedFirst`), the procedural textures store RGB = alpha, every fragment shader premultiplies its tint (`tint.rgb *= tint.a`), and every sprite pipeline blends with source factor `.one` (destination `.oneMinusSourceAlpha`, or `.one` for additive particles; the light composite is the one multiply: source `.destinationColor`, destination `.zero`). A `.sourceAlpha` source factor weights edge pixels by alpha twice and draws a dark fringe round every soft edge (seen 2026-10-01 on the stick figure's disc joints). `TextureManager.addTexture(_:)` registers a ready-made `MTLTexture`; its pixels must be premultiplied too. `DefaultRenderer.addTexture(_ image: CGImage)` decodes and registers an image from outside the bundle (a tool's part images) the same way. `OffscreenRenderTests` pins it: a half-transparent white texel over white stays white, and a half-alpha tint over black is half bright
- Textures load asynchronously; missing textures show magenta error texture. Built-in 1×1 white `defaultTexture` (for solid-color tinting via `AlphaBlendComponent.tintColor`) and 64×64 soft-circle `defaultParticleTexture` (for additive `ParticleShader` glow) are procedurally generated — no asset files
- `ParticleShader` has two blend modes, **additive** (default, order-independent) and **alpha** ("over"). Alpha walks emitters far-to-near (`DrawList` order `.farToNear`: ascending `zOrder`, then texture; every particle of an emitter shares its `zOrder`, so sorting emitters sorts particles). Additive sorts by texture only (`.byTexture`): clamped addition is order-free, so it sorts purely for batching. `ParticleEmitterComponent` owns a pre-allocated `[Particle]` pool with a free-list stack (O(1) spawn); scenes call `emitter.update(dt:)` each frame. Shader writes one uniform per live particle. CPU interpolates `startColor`→`endColor` by `age/lifetime`

## Build & Test

Builds and tests on the Mac host with plain SwiftPM (the fast loop: the GPU tests run on the Mac's Metal device, no simulator), and on the iOS simulator with `xcodebuild`. Both must pass before a release.

```bash
# Mac host
swift build
swift test
swift test -c release -Xswiftc -enable-testing --filter AllocationTests   # zero-allocation claims

# iOS simulator: build
xcodebuild -scheme LiquidMetal2D -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -skipPackagePluginValidation build

# iOS simulator: test
xcodebuild -scheme LiquidMetal2D -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -skipPackagePluginValidation test

# iOS simulator: zero-allocation claims (skipped in Debug; only meaningful optimized)
xcodebuild -scheme LiquidMetal2D -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -skipPackagePluginValidation \
  -configuration Release ENABLE_TESTABILITY=YES test -only-testing:LiquidMetal2DTests/AllocationTests

# Demo app (builds against the local engine; a gate for any engine change)
xcodebuild -project Demo/LiquidMetal2D-Demo.xcodeproj -scheme LiquidMetal2D-Demo \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' -skipPackagePluginValidation build
xcodebuild -project Demo/LiquidMetal2D-Demo.xcodeproj -scheme LiquidMetal2D-Demo \
  -destination 'platform=macOS' -skipPackagePluginValidation build
```

## Notes

- `-skipPackagePluginValidation` is needed for SwiftLint plugin in CLI builds
- Metal shader source is bundled as a resource (`Resources/AlphaBlendShader.metalSource`), compiled at runtime
- All rendering types are `@MainActor`; `DefaultRenderer` is `open` for subclassing; `AlphaBlendShader` is `final`
- `GameObj` is `final` — don't subclass. Compose via `Component` conformers in the component bag
- `@_exported import simd` in TypeAliases.swift — consumers get simd types automatically
- **Small public helpers are `@inlinable`** (math, `Intersect`, `Easing`, simd extensions, `WorldBounds`, `GameObj` component methods). Without it, game code calls them as real functions and generics like `GameObj.get<T>` run unspecialized (verified by disassembling the Release demo). New small, hot public helpers in these files get `@inlinable` too; anything they touch that isn't public needs `@usableFromInline`. Constants are `@inlinable static var x: Float { … }`, not `static let` (a `let` is read through an accessor function across modules). Don't mark large functions inlinable
- **Tests run the real shaders** on the host's or simulator's Metal device: `ShaderTestSupport` builds a `RenderCore` from a bare `PlatformView` (a `UIView` or `NSView` with no window); `OffscreenRenderTests` draws through each shader into a readable 64×64 texture and checks pixels by world position (one world unit per pixel, y up); `SpriteTransformTests` compiles each `.metalSource` with a compute kernel added. Shader or uniform changes must keep these passing
- **Hot plain-data fields are `@exclusivity(unchecked)`** (`GameObj`'s transform fields and `isActive`; the render components' texture, colour and effect fields). Every access to a class's stored `var` otherwise pays a run-time exclusivity check (`swift_beginAccess`); in the 2026-09-25 MassRender profile those checks cost more than all the math. Only plain values get it, never an array, dictionary or reference (`GameObj.components` keeps its check). The attribute covers accesses compiled in this module only; a game turns off its own checks with `SWIFT_ENFORCE_EXCLUSIVE_ACCESS = debug-only`. For the same reason, per-frame loops keep a class's state in locals (`InstanceBatches` in `submit`), and component `parent`s are `unowned let` (a `let` is never checked)
- **Scene code: closures into standard-library algorithms pay an actor-isolation check per call.** A closure written in `@MainActor` code (every scene) is `@MainActor`; passed to `sort`, `filter`, `forEach`, `contains`, `removeAll` and the like, it checks the executor on every call. A 10,000-object sort in the demo's MassRender spent 1.7 ms a frame on it. In per-frame code use a `for-in` loop, a `nonisolated` named function or a `@Sendable` closure. Closures passed to engine APIs (`forEachPotentialPair`, `forEachNear`) don't pay it: the engine is a Swift 6 module
